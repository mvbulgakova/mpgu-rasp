# Как содержать приложение бесплатно

Правило одно: **репозиторий должен оставаться публичным**. На нём держится
вся экономика — Actions, Pages и CDN бесплатны для публичных репозиториев и
платны для приватных. Всё остальное ниже — следствие.

Сегодня проект не тратит ни рубля и не должен начать.

## Кто что делает

| Слой | Где живёт | Что стоит | Реальные лимиты |
|---|---|---|---|
| Парсер, 2 раза в сутки | GitHub Actions | 0 ₽ | публичный репо — **минуты не тарифицируются**; приватный — 2000 мин/мес, наш прогон съел бы их за ~2 недели |
| Хранилище данных | ветка `data` в том же репо | 0 ₽ | мягкий лимит репозитория ~1 ГБ; сейчас данные ~10 МБ |
| Раздача данных | jsDelivr (`cdn.jsdelivr.net/gh/…@data`) | 0 ₽ | без жёсткого потолка, публичные репо; кэш ~12 ч |
| PWA | GitHub Pages | 0 ₽ | 100 ГБ/мес трафика, 1 ГБ сайт, 10 сборок/час |
| Telegram-бот расписания | GitHub Actions, long-polling | 0 ₽ | тот же счёт минут; вебхук не нужен |
| Обратная связь | GitHub Issues | 0 ₽ | `GITHUB_TOKEN`: 1000 запросов/час на репозиторий |
| Android | APK в GitHub Releases | 0 ₽ | Google Play — единоразовые $25, **не обязателен** |

Ноль внешних аккаунтов. Ни Cloudflare, ни VPS, ни базы данных, ни платного
CDN. Единственный секрет, который нужно завести руками, — `BOT_TOKEN` от
@BotFather.

## Два разных бота — не перепутайте токены

**Бот расписания** (этот репозиторий) и **бот приёмной кампании** (живёт
отдельно, работает) — разные боты у @BotFather с разными токенами.
`secrets.BOT_TOKEN` здесь принадлежит боту расписания и только ему.

Подставить сюда токен приёмки нельзя: воркфлоу начнёт отвечать её
подписчикам расписанием, а `deploy-bot.yml` переставит вебхук и оборвёт
доставку. Снятие вебхука со стороны бота не откатывается — регистрировать
заново придётся вручную.

## Почему бот живёт на Actions, а не на Cloudflare

В репозитории есть два бота: `scraper/telegram_bot.py` (long-polling на
Actions) и `cloudflare-worker-bot/` (вебхук). **Одновременно работать они не
могут** — Telegram отдаёт обновления либо через `getUpdates`, либо на
вебхук, третьего не дано. Так что это не «два бота», а выбор одного.

Выбран Actions-бот:

- не нужен аккаунт Cloudflare и деплой;
- `GITHUB_TOKEN` уже есть в раннере, поэтому обратная связь пишет в Issues
  без отдельного PAT, который пришлось бы хранить и ротировать;
- обновление кода = обычный push, без `wrangler`.

Цена выбора: ответ приходит за секунды, но между ранами бывает окно —
крон GitHub в часы пик опаздывает. Воркер отвечал бы всегда мгновенно.
Если однажды это станет важно, переключение обратимо: включить вебхук,
выключить крон `bot-poll.yml`, добавить в воркер PAT для Issues.

## Что убьёт бесплатность (и чего не делать)

1. **Сделать репозиторий приватным.** Мгновенно включает счётчик минут и
   отключает jsDelivr. Это самое дорогое из возможных решений.
2. **Учащать крон.** Скрапер два раза в сутки — осознанно: расписание
   меняется не чаще. Каждый лишний запуск — это 17 параллельных джобов.
3. **Собирать Android в каждом пуше.** Сейчас сборка привязана к
   `paths: android/**`; не снимайте фильтр.
4. **Заводить базу данных.** JSON в ветке + CDN уже дают то же самое
   бесплатно и с бесплатной историей изменений через `git log`.
5. **Хранить в `data` бинарники.** Ветка растёт навсегда: git хранит все
   версии. Исходные PDF там не нужны — только распарсенный JSON.

## Что стоит денег, но не обязано

- **Google Play, $25 единоразово.** Пока APK раздаётся через Releases и
  ссылку в боте, это не нужно. Понадобится, когда захотите автообновления
  и поиск в маркете.
- **Свой домен, ~200 ₽/год.** Pages работает на `*.github.io` бесплатно.
- **Платный VLM для скан-PDF.** 90 файлов без текстового слоя остаются
  непрочитанными. Экономически это ~1500 ₽ разово за прогон Gemini/Claude
  по ним. Пока правило проекта — «garbled code хуже, чем missing group» —
  лучше не показывать эти группы вовсе.

## Сигналы, что пора вмешаться

- Actions начали показывать счёт за минуты → репозиторий стал приватным.
- jsDelivr отдаёт 404 на `@data` → ветка `data` пропала или пуш сломался.
- В Issues пошёл поток от бота → скорее всего сломался парсер, а не люди.
  Смотреть надо на источник, а не на инбокс.
- `data-freshness.yml` завёл issue → обход не обновлял данные дольше 8 часов.
