# Навигация по направлению и профилю (2026-08-27)

Студент помнит своё **направление** («44.03.01 Педагогическое образование»)
и **профиль** («Обществознание и Экономико-правовое образование»), а код
группы — «ВОП40-ПФК2501» — не помнит почти никогда. До этой правки все три
клиента (PWA, Android, Telegram-бот) предлагали искать именно по коду.

Оба поля есть в самих источниках МПГУ — в шапке сетки, **по колонкам**,
ровно над кодами групп. Их просто никто не читал.

## Один экстрактор на все парсеры

`scraper/normalizer/schedule_normalizer.extract_column_headers(table, data_col)`
→ `{col_idx: {"direction": …, "profile": …}}`.

Он лежит в нормализаторе, а не в `pdf_parser`, сознательно: у проекта уже
есть история D31/D38/D39/D41, где один и тот же регекс жил в пяти копиях и
чинился по одной. Экстрактор вызывают `pdf_parser`, `excel_parser` и
`gsheets_parser`; `docx_parser` и `nextcloud_parser` получают его бесплатно,
потому что ходят через `pdf_parser._parse_tables`.

## Что пришлось выдержать: формы подписи в живых источниках

| Форма | Где встретилась |
|---|---|
| `Код, наименование направления/специальности` + `Направленность (профиль)` | arts, journalism, philology, languages |
| Перенос **внутри слова**: `Код, наименован ие направлени я` | journalism, philology (pdfplumber) |
| Опечатка источника: `Код, наименвание направления:` | history (xlsx) |
| Одно слово: `Направление` / `Профиль` / `специальность` | math, geography |
| Подпись и значение в одной ячейке: `Направление 44.03.02 …` | preschool |
| Подпись **внутри** ячейки колонки: `108 ГРУППА: Направленность: «…»` | pedagogy (docx) |
| `Специальность: «Психология и педагогика…»` — это **профиль** | pedagogy |

Отсюда три правила:

1. **Сравнение по «расшитой» метке.** Перед матчингом из подписи выкидываются
   все пробелы, поэтому перенос внутри слова перестаёт что-либо значить.
2. **Профиль проверяется раньше направления.** «Направленность» содержит
   «направлен», и наивный порядок читает профиль как направление.
3. **Направление узнаётся по коду ОКСО** (`37.05.01`) в начале значения, а не
   по слову подписи. Иначе pedagogy'шная «Специальность: «Психология и
   педагогика…»» уезжает в направления.

## Протяжка объединённых ячеек — и где она обязана остановиться

Одно направление накрывает несколько колонок-групп объединённой ячейкой, а
извлекатели таблиц кладут текст только в первую из них. Поэтому значение
протягивается вправо — но:

- **Собственное значение колонки всегда бьёт протяжку.** В geography профиль
  расписан на две строки: общая часть в строке с подписью, уточнение в
  безымянной строке под ней. Без этого правила объединённое «География и
  Иностранный язык» затирало соседнюю «Общую географию».
- **Чужой непустой текст обрывает протяжку.** В pedagogy соседние колонки
  несут РАЗНЫЕ направления в своих же ячейках.
- **Строка занятий не может быть продолжением шапки.** Строка-продолжение
  обязана быть без подписи, без переносов в ячейках, без времени и без кодов
  групп, и берётся ровно одна.

## ИСГО: несколько групп в одной колонке

social/sport публикуют колонку с четырьмя кодами и четырьмя профилями
списком. Профили раздаются позиционно — **только если счёт сошёлся**. Если
профилей три, а групп четыре (две группы одной «Юриспруденции»), профиль не
проставляется вовсе: список из трёх профилей не является профилем ни одной
из этих групп. Точность важнее полноты.

## Что изменилось в клиентах

- **Данные:** `direction` и `profile` в файле группы, в манифесте института
  (`institutes/<id>/schedule.json`) и в `meta/groups.json`.
- **PWA:** список групп сгруппирован по направлению → профилю; поиск ищет по
  всем трём полям. Источники без направления показываются по-старому, по
  уровню образования.
- **Android:** `GroupCatalog` (institute → direction → profile → group) с
  сворачиваемыми секциями; тот же поиск в `GroupsScreen` и `OnboardingScreen`.
- **Telegram-бот:** принимает «журналистика» так же, как «ВОП40-ПФК2501»,
  и в списке совпадений показывает профиль вместо голого кода.

# Чётность недели: НАД / ПОД чертой (тот же день)

Вторая половина задачи. Все четыре клиента считали чётность недели по
**ISO-номеру недели** (`week % 2`). Это неверно, и неверно грубо.

## Что показал официальный документ

`scratchpad/sources/pedagogy/000_расписание-недель-надпод-чертой-…pdf` —
скан без текстового слоя, поэтому его никто не читал. Я вытащил из PDF обе
встроенные JPEG-страницы и прочитал их глазами. Документ задаёт чётность
каждой недели года явно, строкой на неделю:

```
31.08.2026 – 06.09.2026   НАД чертой
07.09.2026 – 13.09.2026   ПОД чертой
…
22.02.2027 – 28.02.2027   ПОД чертой
01.03.2027 – 07.03.2027   ПОД чертой      ← чередование рвётся
…
05.07.2027 – 11.07.2027   ПОД чертой
```

## Две ошибки вместо одной

1. **ISO-номер недели инвертирован весь первый семестр.** 2026 год содержит
   53 ISO-недели, поэтому на переходе через Новый год чётность ISO
   переворачивается относительно календаря МПГУ. С 31.08.2026 по 28.12.2026
   — **18 недель подряд** — приложение показывало бы расписание ЧУЖОЙ недели.
   Проверяемо: 14.09.2026 — ISO-неделя 38 (чётная), а по документу это НАД
   чертой, то есть нечётная.

2. **Чередование от начала года тоже не работает.** Между 22.02 и 01.03
   идут две ПОД-недели подряд — стык семестров. Любая формула здесь врёт;
   нужна таблица.

## Как сделано

`scraper/academic_calendar.py` держит таблицу («o» = НАД, «e» = ПОД, буква
на неделю от 31.08.2026) и публикует её в `meta/week_parity.json`. За
пределами опубликованного года чётность достраивается чередованием от
ближайшего известного края — и это честно помечено догадкой в коде.

Все клиенты читают таблицу из data-ветки, встроенная копия — запасной
вариант: новый учебный год не требует ни релиза приложения, ни передеплоя
воркера.

| клиент | было | стало |
|---|---|---|
| Android | `WeekFields.ISO.weekOfWeekBasedYear() % 2` | `WeekParity.forDate(date, calendar)`, календарь из `meta/week_parity.json` |
| PWA | `getISOWeek(today) % 2` | `isEvenWeek(today, weekCalendar)` |
| Cloudflare-бот | самописный ISO-номер | таблица + `meta/week_parity.json` |
| Python-бот | `d.isocalendar()[1] % 2` | `academic_calendar.is_odd_week` |

Тесты — по строкам скана, в трёх местах: `test_academic_calendar.py`,
`WeekParityTest.kt` и прогон JS-реализации на тех же 11 датах.
